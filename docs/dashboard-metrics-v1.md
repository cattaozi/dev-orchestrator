# Dashboard 指标定义（V1）

## 一、目标

Dashboard 不是“报表页”，而是“下一步行动页”。  
指标用于回答：**进度如何、状态如何、哪里卡住、下一步做什么。**

## 二、指标分层

### A. 执行状态层（实时）

1. 运行中项目数
- 定义：存在至少一个 running 服务的项目数量
- 数据来源：`project_services.status`

2. 活跃 Session 数
- 定义：状态为 running/pending 的 Session 数
- 数据来源：`sessions.status`

3. 阻塞任务数
- 定义：状态为 blocked 的任务数
- 数据来源：`issues.status`（或后续 `tasks.status`）

### B. 推进效率层（日维度）

1. 今日完成任务数
- 定义：当天状态变为 done 的任务数

2. 24 小时净推进
- 定义：`done_count - new_todo_count`

3. 平均任务停留时长
- 定义：任务从创建到 done 的平均耗时（done 任务样本）

### C. 个人节奏层（情绪价值）

1. 连续推进天数
- 定义：连续每天至少完成 1 个任务的天数

2. 今日有效会话数
- 定义：有“结果总结”且非空的 Session 数

3. 卡点解除数
- 定义：blocked -> doing/done 的任务数

## 三、展示建议

- 顶部 4 张核心卡片（运行项目、活跃会话、阻塞任务、今日完成）
- 中部两列：`项目状态` + `今日任务`
- 底部：`最近 Session 总结流`

## 四、V1 计算策略

- 优先使用现有表计算，减少 schema 变更成本。
- 复杂指标可先离线计算（API 聚合），后续再做物化优化。
