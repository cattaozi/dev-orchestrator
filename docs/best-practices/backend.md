# Backend 编码最佳实践

适用范围：`web/backend/**`、`storage/**`

## 1. 路由与服务分层

- 路由层负责参数校验、鉴权与返回格式，业务逻辑放入 `services`。
- 遵守 FastAPI 路由顺序：具体路由在前，泛化路由在后。
- 避免使用容易冲突的路径模式（如 `/{id}/action`）。

## 2. 配置与安全

- 数据库连接、监听地址、端口、密钥等必须来自环境变量。
- 新增环境变量时，必须同步更新 `.env.example` 与 README 配置章节。
- 严格校验外部输入，避免命令拼接、SQL 注入和路径越权风险。

## 3. 错误处理与日志

- 统一异常输出结构，确保前端可稳定解析。
- 关键路径记录结构化日志（请求路径、资源 ID、状态码等）。
- 日志中禁止输出敏感信息（密码、Token、连接串明文）。

## 4. 数据库约束（PostgreSQL）

- 表结构变更必须有迁移方案，禁止手工改线上库。
- 事务边界清晰，失败即回滚，保证一致性。
- 为高频查询建立索引，并通过实际查询计划验证收益。

## 5. 测试与回归

- 修改服务逻辑应补充对应单元测试。
- 修改接口行为应至少覆盖成功/失败两类场景。
- 涉及数据变更的改动需要附带回滚说明。
