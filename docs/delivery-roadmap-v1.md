# 交付路线（V1）

## Phase 0：收敛（1~2 天）

- 确认三核心概念：`项目/任务/Session`
- 冻结非 MVP 功能（PRD 重流程、复杂日志展示）
- 定义 Dashboard 指标口径

## Phase 1：可用工作台（第 1 周）

目标：每天可用

- 项目基于文件夹管理（已部分具备，继续强化）
- 服务受控管理稳定化（多服务、状态准确、轻量 UI）
- 任务列表可推进（todo/doing/done/blocked）
- Session 可关联任务并展示结果说明

验收：
- 能用该系统完成至少 1 个真实任务闭环
- 用户不需要切回多个窗口查状态

## Phase 2：可持续推进（第 2 周）

目标：愿意持续使用

- Dashboard 首屏完成（状态 + 进度 + 阻塞）
- Session 自动总结（产出级摘要）
- 今日焦点区（Top Tasks）
- 收工视图（未完成项 + 运行服务快照）

验收：
- 每天打开 Dashboard 后 10 秒内知道“下一步做什么”
- 至少连续 3 天使用

## 风险与应对

1. 方向漂移回“聊天 UI”
- 应对：需求评审优先问“是否提升任务推进效率”

2. 指标过多导致复杂
- 应对：V1 只保留 4 个核心指标

3. 数据来源不稳定
- 应对：先做 API 聚合，后续再做数据层优化

## 建议里程碑评审点

- M1（第 3 天）：信息架构评审
- M2（第 7 天）：Phase 1 功能验收
- M3（第 14 天）：Phase 2 体验验收与继续/收缩决策
